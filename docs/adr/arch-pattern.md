## Контекст

Разработка ИИ ассистента, обеспечивающего выполнение следующих функций,:
с возможностью ручного "запуска" каждой из операций в отдельности:

* Поиск в Интернете
* Поиск в Локальной Базе знаний
* Обработка найденной информации с помощью LLM
* Использование инструментов для работы с файловой системой (сохранение результатов).

Дополнительно ИИ Ассистент должен обеспечивать возможности:

* Ручного управления планами выполнения исследования (CRUD)
* Более атомарного управления контекстом
  (Просмотр\Редактирование\Удаление найденной информации в виде отдельных поименованных блоков)
* Сохранение планов и контекстов в базе знаний для последующего переиспользования.

Полностью постановка задачи описана в [prd.md](../prd.md)

## Решаемый вопрос

Требуется выбрать один из архитектурных стилей:

- ReAct,
- Оркестрация,
- Хореография.

## Решение

Исходя из состава операций можно выделить только две задачи, которые можно решать с помощью агентов:
поиск в Интернете, Анализ данных с помощью LLM. Все остальные функции однозначно должны быть реализованы с помощью инструментов.

Ограничение: В следующих версиях возможно использование еще и агента планировщика, который из-за ограниченного времени пока не рассматривается.

Так как количество агентов крайне невелико, наиболее оптимальным решением будет использование паттерна ReAct и реализация всего функционала при помощи инструментов.

## Последствия

### Положительные

- **Простота реализации** — паттерн ReAct хорошо изучен и имеет множество готовых библиотек и примеров.
- **Прозрачность** — каждый шаг агента (Thought → Action → Observation) логгируется и может быть отслежен пользователем.
- **Гибкость** — инструменты могут быть добавлены или изменены без изменения логики агента.
- **Предсказуемость** — при малом количестве агентов (2: поиск и анализ) ReAct работает стабильнее, чем сложные многоступенчатые оркестраторы.
- **Легкость отладки** — пошаговое выполнение позволяет точно определить, на каком этапе возникла ошибка.

### Отрицательные / Риски

- **Повышеня нагрузка на пользователя** - за счет самостоятельного планирования и отдельного выполнения операций.
- **Ограничение масштабируемости** — при увеличении количества агентов ReAct становится сложным в поддержке, требуется переход к оркестрации или хореографии.
- **Отсутствие глобального планирования** — ReAct не имеет централизованного планировщика, что может приводить к неоптимальному порядку выполнения задач.
