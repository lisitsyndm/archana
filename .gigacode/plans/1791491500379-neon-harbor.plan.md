# Проект изменений: Выделение DB-слоя в отдельный архитектурный слой

## Цель

Разделить ответственность за взаимодействие с БД, убрав прямые `psycopg2`-зависимости из `core/plan.py` и `tools/database.py`, создать единый, переиспользуемый, тестируемый Data Access Layer (DAL).

## Текущее состояние

| Модуль | Проблема |
|--------|----------|
| `tools/database.py` | Прямой `psycopg2`-импорт, нет error handling, нет connection pooling, connection leak при исключениях |
| `core/plan.py` | Прямой `psycopg2`-импорт, дублирование логики подключения, `print()` вместо логирования |

| **Общее** | Нет единого источника DB-конфигурации, нет context manager'ов, нет transaction management |

## Предлагаемая архитектура

```
┌─────────────────────────────────────────────┐
│                  tools/                     │
│  database.py, plan.py, context.py, ...      │
│         ↑ uses DAL API                      │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│              data/ (NEW)                    │
│  ┌─────────────────────────────────────┐   │
│  │ repository.py   — interfaces/ABC    │   │
│  │ pg_repository.py  — PostgreSQL impl │   │
│  │ connection.py   — pooling, config   │   │
│  │ exceptions.py   — DAL exceptions    │   │
│  └─────────────────────────────────────┘   │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│         psycopg2 / pgvector (infra)         │
└─────────────────────────────────────────────┘
```

## Изменения по файлам

### 1. NEW: `data/exceptions.py`
- `DatabaseError` — базовое исключение DAL
- `KnowledgeNotFoundError` — запись не найдена
- `PlanNotFoundError` — план не найден
- `ConnectionError` — проблема с подключением

### 2. NEW: `data/connection.py`
- `get_connection_params()` — единый источник DB-конфигурации из env
- `create_pool()` — connection pooling через `psycopg2.pool.ThreadedConnectionPool`
- `get_pool()` — singleton pool (lazy init)
- Context manager для safe connection/cursor lifecycle

### 3. NEW: `data/repository.py`
- `KnowledgeRepository` — ABC интерфейс:
  - `search(query_embedding: list[float], limit: int = 1) -> list[Knowledge]`
  - `upsert(name: str, text: str, embedding: list[float]) -> None`
- `PlanRepository` — ABC интерфейс:
  - `get_by_id_or_name(identifier: str) -> Plan`
  - `save(plan: Plan) -> None`
  - `delete_items(plan_id: int) -> None`

### 4. NEW: `data/pg_repository.py`
- `PostgresKnowledgeRepository` — реализация `KnowledgeRepository`
- `PostgresPlanRepository` — реализация `PlanRepository`
- SQL queries централизованы здесь
- Transaction management через `conn.commit()` / `conn.rollback()`

### 5. MOD: `tools/database.py`
- Удалить прямые `psycopg2` импорты
- Использовать `PostgresKnowledgeRepository` из `data/`
- `LoadFromDatabaseCommand` → `repo.search()`
- `SaveToDatabaseCommand` → `repo.upsert()`
- Убрать дублирование embedding generation (вынести в shared utility)

### 6. MOD: `core/plan.py`
- Удалить прямые `psycopg2` импорты из `loadFromDatabase()` / `saveToDatabase()`
- Использовать `PostgresPlanRepository` из `data/`
- Методы `loadFromDatabase()` / `saveToDatabase()` делегируют репозиторию

### 7. NEW: `data/__init__.py`
- Экспорт публичного API: `KnowledgeRepository`, `PlanRepository`, `get_pool`
